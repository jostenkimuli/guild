Step-by-step setup

1. Install dependencies
npm install
2. Start the local Supabase stack

First run pulls and starts the necessary Docker images:

npm run db:start
3. Configure environment variables
copy .env.example .env.local

Fill in the keys printed by supabase status:

NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:55421
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key>
SUPABASE_SERVICE_ROLE_KEY=<service role key>

Optional: NEXT_PUBLIC_APP_HOST sets the base hostname used by the subdomain feature (defaults to localhost).

4. Apply migrations + seed data
npm run db:reset

This reapplies every migration in supabase/migrations/ from scratch and runs supabase/seed.sql. Use it after pulling new schema work; it is non-destructive to anything outside the local database.

5. Run the app
npm run dev

Open http://localhost:3000.

After any schema change
Re-run npm run db:reset and npm run db:types, and commit the regenerated src/lib/supabase/database.types.ts. Details in Database & Migrations.

Windows notes

  • This host blocks *.ps1 command shims — use npm.cmd and supabase.cmd.
  • The default Supabase 5432x port range is reserved by Hyper-V. Ports are remapped in supabase/config.toml: API 55421, DB 55422, Studio 55423. Do not revert.
  • next.config.ts sets allowedDevOrigins: ["*.localhost"] so subdomains like a-sample-school.localhost:3000 work in dev.
