Engineering Process

TheGuild is built in one-week sprints. Process artifacts live in docs/agile/ and are authoritative: working agreements, Definition of Done, product backlog, and the sprint plan.

Team rituals

  • One-week sprints with a planning session and a retro.
  • The Definition of Done applies to every item — nothing ships without it.
  • One PR per backlog item; keep diffs small.
  • Every feature traces back to a user story in the backlog.

Working agreements (WORKING_AGREEMENTS.md)

  • Server components by default; client components only for interactivity.
  • RLS is the security boundary; every new table gets RLS + explicit GRANTs.
  • Regenerate and commit DB types after every schema change.
  • Prefer shadcn/ui components; no hand-rolled duplicates.
  • No secrets in code or repo.

Definition of Done (DEFINITION_OF_DONE.md)

An item is done only when it passes all of:

#Criterion
1Feature works locally end-to-end.
2npm run lint — no errors.
3npm run typecheck — passes.
4npm run build — clean production build.
5Schema changes ship as migrations; db:reset applies from scratch.
6RLS enabled + explicit GRANTs + row-level policies, verified with positive and negative tests.
7db:types regenerated and committed.
8No secrets leaked.
9Meets the user story’s acceptance criteria.
10Keyboard navigable, readable at default text size, no axe contrast failures.
11Sensible empty / loading / error states.
12Uses shadcn/ui components.
13Backlog item marked done; docs updated; no dead code.
