Grants & triggers

  • This Supabase version does not auto-grant privileges to anon/authenticated — every new table gets explicit GRANTs in its migration.
  • RLS is enabled on every table; policies are the security boundary (details in Auth, Roles & RLS).
  • on_auth_user_created trigger auto-creates a profiles row on signup.
  • set_updated_at trigger maintains updated_at on key tables.
  • SECURITY DEFINER helpers resolve any curriculum row (deep or shallow) to its Space so RLS can scope through it; profile role/status/delegation flags are locked by a trigger to the super admin (and, for ecosystem-admin status, to a delegated program admin).

Seed data (supabase/seed.sql)

  • 6 accounts covering every platform role (see demo accounts).
  • 1 ecosystem: “A Sample School Ecosystem” (primary school, Nairobi, Kenya) with full school metadata (director, headteacher, location).
  • 1 space: “Primary Mathematics Space” (department) with memberships: space admin, teacher (ecoadmin + testteacher), learner.
  • Invitation code MATHLAB (learner, max 50 uses).
  • Published curriculum “Primary Mathematics” (2026): 3 goals, 3 grades, terms, 6 topics, 12 learning objectives, 4 published self-paced lessons (each with overview page, 3 activities, 1 assessment), 5 shared resources, 6 teaching-guidance notes, 3 unit projects, 2 curriculum evaluations (Term 1: 72.5%, Term 2: 78%).
  • Syllabus: pass mark 50%, breakdown Homework 20% / Mid-term 30% / Final exam 50%.

Schema change workflow

  1. Add a migration in supabase/migrations/ with the new timestamp filename.
  2. Enable RLS on new tables and add explicit GRANTs.
  3. Run npm run db:reset (reapplies migrations + seed from scratch) and verify in the app.
  4. Run npm run db:types to regenerate src/lib/supabase/database.types.ts.
  5. Commit the migration and the regenerated type diff together.
  6. Verify with positive and negative RLS tests (see DoD in Engineering Process).
Ports
Local stack ports are remapped in supabase/config.toml (API 55421, DB 55422, Studio 55423) because the default 5432x range is Hyper-V-reserved on this host. Do not revert.
